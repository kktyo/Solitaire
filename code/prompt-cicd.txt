# やりたいこと
このリポジトリのソース（`code/server` Spring Boot API、`code/front` Flutter）に適合する CI/CD を、**Azure Container Apps + Azure SQL** 契約に合わせて設計する。
アプリ機能の追加や API 契約の変更はしない。正本は `infra/azure-container-apps-契約.txt` と `doc/03.設計/設計.md` 5.4〜5.6。

# 前提
- API は Docker イメージ。本番は **Azure Container Apps Consumption**（最小 0、最大 1）
- イメージ置き場は **GitHub Container Registry**。ACR は使わない
- デプロイスロット・App Service Plan は使わない
- DB は Azure SQL（無料オファーまたは Basic）。Flyway。CI は本番 SQL に繋がない
- JWT ステートレス。分散ロックなし
- 秘密（`DB_*`、`JWT_*`）はリポジトリに置かない

# 提案してほしいこと（必須）

## 1. Container Apps と SQL
具体値を 1 案に絞る。

- Consumption、min 0 / max 1、CPU 0.5 / メモリ 1Gi、イングレス HTTPS、targetPort 8080
- ヘルス: `GET /api/v1/health`。UI: `GET /`（Flutter Web を同一コンテナで配信）
- シークレット: `DB_URL` `DB_USER` `DB_PASSWORD` `JWT_ACCESS_SECRET` `JWT_REFRESH_SECRET`
- Azure SQL: 無料オファー優先、なければ Basic。ファイアウォールは Azure サービス許可
- Log Analytics は課金源なので既定の大量収集をしない
- Bicep の項目一覧と命名（`infra/main.bicep` と一致させる）

## 2. GitHub Actions
| ワークフロー | トリガー | 内容 |
| --- | --- | --- |
| CI server | `code/server/**` 等 | Gradle / JUnit / Testcontainers |
| CI front | `code/front/**` | `flutter test` |
| CD | main（front/server/docker/infra） | `flutter test` と Gradle test が両方成功してからイメージを GHCR へ push → Container Apps 更新 → `/api/v1/health` と `/` |

OIDC（`azure/login`）。必要な Secrets / Variables を列挙。フロントまたはサーバのテスト失敗で CD のデプロイを止める。

## 3. CI の SQL
本番 Azure SQL に CI から繋がない。GitHub-hosted + Testcontainers の SQL Server。CI 用と Container Apps 用の接続先を分離する。

# 完了条件
- 契約ファイル（SQL + Container Apps、ACR/スロットなし）と食い違わない
- CI の SQL と本番 SQL が混ざらない
