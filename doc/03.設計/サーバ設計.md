## 1. 技術選定

| 項目 | 選定 | 理由 |
| --- | --- | --- |
| 言語 | Java 21（LTS） | Spring Boot 3 系の標準 |
| フレームワーク | Spring Boot 3（Web / Validation / Security / Data JDBC または JPA） | REST とトランザクション |
| DB アクセス | Spring Data JDBC + 明示 SQL、または JPA。**本設計は JDBC テンプレート／Data JDBC を推奨** | `board_json` が大きく、対局は行ロック付き更新が中心 |
| マイグレーション | Flyway | スキーマの再現 |
| 認証 | 自前 JWT（jjwt または Nimbus）。Spring Security フィルタで Bearer 検証 | 外部 IdP なし |
| パスワード | BCrypt（strength 10 以上） | 要件どおり復元不可 |
| JSON | Jackson。Board はドメインへマップしてから永続化時に文字列化 | 不正 JSON を DB に書かない |

ビルド: Gradle。パッケージ名: `com.solitaire`（アプリ名に合わせ変更可。一度決めたら固定）。

## 2. レイヤとパッケージ

```
com.solitaire
  api              REST、DTO、例外ハンドラ
    auth
    game
  application      ユースケース（トランザクション境界）
  domain.auth      メール正規化、トークンハッシュ
  domain.game      規則エンジン（UI・Spring 非依存）
  infra.db         Repository、行マッピング
  infra.security   JWT 発行／検証、PasswordEncoder
  config           セキュリティ、CORS、Clock
```

依存方向: `api` → `application` → `domain`。`infra` は `application` がインタフェース経由で使う。**`domain.game` は Spring アノテーションを付けない。**

| レイヤ | やってよいこと | やってはいけないこと |
| --- | --- | --- |
| api | バリデーション、HTTP マッピング、401/403 | 規則判定、SQL |
| application | 1 ユースケース 1 トランザクション、権限（本人の対局か） | HTTP 型への依存 |
| domain.game | 配札・合法・適用・クリア判定・操作詰み・ソルバ | 時刻の永続方針以外の I/O |
| infra | SQL、JWT、BCrypt | 業務分岐（クリア認定の条件など） |

## 3. 認証設計

### 3.1 トークン

**Access JWT（60 分）**

| claim | 内容 |
| --- | --- |
| `sub` | `userId`（UUID 文字列） |
| `typ` | `access` |
| `iat` / `exp` | 発行・期限 |

署名: HS256、`JWT_ACCESS_SECRET`（256 bit 以上）。DB 照合はしない（期限切れは 401）。

**Refresh JWT（30 日）**

| claim | 内容 |
| --- | --- |
| `sub` | `userId` |
| `jti` | `refresh_tokens.id` |
| `typ` | `refresh` |
| `iat` / `exp` | |

受信時: 署名検証 → `jti` で行取得 → `revoked_at IS NULL` かつ `expires_at > now` かつ `token_hash` が一致。  
保存は **生トークンの SHA-256（hex または Base64）**。BCrypt はリフレッシュの高頻度検証に向かない。

リフレッシュ成功時: 新 refresh を発行し、旧行を `revoked_at = now`（ローテーション）。アクセスも新規発行。

ログアウト: Bearer の利用者に属する当該 `jti` のみ revoke。他人のトークンは 403 または 204 で何もしない（存在漏洩を避けるなら 204 統一）。

### 3.2 メール・パスワード

- 正規化: `trim` + 小文字。UNIQUE はこの値。
- パスワード: 8 文字以上。上限 72（BCrypt）。API は 400 `VALIDATION_ERROR`。
- ログイン失敗: メールの有無でメッセージを変えない。同一 `401`。

### 3.3 フィルタ

1. `/api/v1/auth/register`, `/login`, `/refresh` は匿名。
2. その他 `/api/v1/**` は Bearer 必須。
3. パスに存在するが認証切れは 401。対局 ID が他人ならユースケースで 403。

## 4. 対局ユースケース

すべて対象行を `UPDLOCK, ROWLOCK`（SQL Server）相当で読む。同一利用者の進行中はフィルタ一意索引で二重 INSERT を防ぐ。

### 4.1 GameApplicationService（責務）

| メソッド | API | 要点 |
| --- | --- | --- |
| `getCurrent` | GET current | IN_PROGRESS を返す。**timing は変更しない** |
| `resume` | POST resume | IN_PROGRESS のみ。`timing_started_at == null` なら now。既に非 null なら維持 |
| `pause` | POST pause | 非 null なら `elapsed += now - started`、`started = null` |
| `create` | POST games | 4.2 |
| `applyMove` | POST moves | 4.3 |
| `undo` | POST undo | 4.4 |
| `listMyResults` | GET results/me | `game_results` を `cleared_at DESC`、`limit` 既定 1 最大 20 |

`CLEARED` / `ABANDONED` に対する resume / pause / moves / undo は 422（または 409）。本フェーズは 422 に統一してよい。

### 4.2 新規

1. 進行中をロック検索。
2. `abandonExisting == true` なら `status = ABANDONED`、`timing_started_at = null`。
3. `domain.game.Deal.winnableBoard(secureRandom)` で Board（ソルバが解を見つけた山）。
4. INSERT。`version=0`。`game_moves` は空。

`SecureRandom` を使う。シード固定はテスト専用で本番設定に置かない。

### 4.3 手の適用

1. 対局ロック取得。`user_id` 不一致は 403。なし 404。
2. `status != IN_PROGRESS` → 422。
3. `request.version != games.version` → 409、`details.game` に正本。
4. Board を JSON からドメインへ。`GameRules.apply(board, move)`。
   - 不正: 422。UPDATE しない。
5. 時間: `elapsed_ms` を `accrue(now)`。継続なら `timing_started_at = now`。クリアなら加算後 `null`。
6. `move_count += 1`、`version += 1`、`board_json` 更新、`updated_at = now`。
7. `game_moves` INSERT: `kind=APPLY`、`seq=max+1`、`move_json`、適用**前**の board / move_count / elapsed。
8. クリア: `status=CLEARED`、`cleared_at=now`、`game_results` INSERT（手数・経過は更新後の値）。

停止中（`timing_started_at` が null）に手が来た場合: 加算は 0 とし、クリアでなければ `timing_started_at = now` にする（操作した時点から計測再開。pause 中のチート進行で時間を止め続けない）。

### 4.4 アンドゥ

未打消の直近 APPLY の求め方（`seq` 降順）:

```
depth = 0
for row in moves desc:
  if kind == UNDO: depth++
  else if kind == APPLY:
    if depth == 0: return this row   // 打ち消す対象
    else: depth--
return none → 422 CANNOT_UNDO
```

復元: `board_json` と `move_count` を対象 APPLY の `*_before` へ。`elapsed_ms` は現状維持のうえ `accrue`（アンドゥも対局中操作のため計測は進めてよい。手数だけ戻る）。`version += 1`。UNDO 行を追加（`move_json` は null、`board_before` はアンドゥ直前の盤面）。

クリア後は履歴があっても 422。

### 4.5 accrue（経過時間）

```
accrue(game, now, continueTiming):
  if game.timingStartedAt != null:
    game.elapsedMs += max(0, now - timingStartedAt)
  if continueTiming:
    game.timingStartedAt = now
  else:
    game.timingStartedAt = null
```

`now` は注入した `Clock`（テストで固定可能）。

## 5. 永続化

### 5.1 物理（SQL Server）

論理定義は `DB.md`。追加:

- すべての `datetime2` は UTC。アプリはオフセットなしで書く。
- `board_json` はドメイン検証済み JSON 文字列のみ。
- フィルタ一意:

```sql
CREATE UNIQUE INDEX UX_games_user_in_progress
  ON games(user_id)
  WHERE status = N'IN_PROGRESS';
```

- 対局更新:

```sql
SELECT * FROM games WITH (UPDLOCK, ROWLOCK)
 WHERE id = @id;
```

マイグレーションは Flyway `V1__init.sql` で 5 テーブル + 索引。

### 5.2 Repository

| インタフェース | 操作 |
| --- | --- |
| `UserRepository` | insert、findByNormalizedEmail、findById |
| `RefreshTokenRepository` | insert、findById、revoke、deleteExpired |
| `GameRepository` | insert、findById、findInProgressByUser、update |
| `GameMoveRepository` | insert、listByGameOrderBySeq |
| `GameResultRepository` | insert、listByUserOrderByClearedAtDesc |

アンドゥ判定は当該対局の `game_moves` を seq 降順で読む（本フェーズは件数制限なし。極端な手数でも単対局想定）。

### 5.3 Board JSON

永続化前に不変条件を検証する。失敗は 500（正本破損）または適用前なら 422。不変条件は [規則エンジン設計.md](./規則エンジン設計.md) 8 章。

## 6. API 実装メモ

- ベースパス `/api/v1`。コンテキストパスは空（または `/`）。
- バリデーション失敗は 400、`details` にフィールド名。
- `VERSION_CONFLICT` / `INVALID_MOVE` の `details.game` は GameResponse（`stalemate` を含む）。
- 例外は `@RestControllerAdvice` で要件のエラー本文に正規化。未捕捉は 500 `INTERNAL_ERROR`（内部例外メッセージはクライアントに出さない）。
- タイムアウト 15 秒はクライアント側。サーバはリクエストスレッドで同期処理（本フェーズ）。

DTO 名は API.md の型に合わせる: `CardDto`, `BoardDto`, `GameResponse`, `MoveRequest`。ドメイン `Board` との変換は application または専用 Mapper。

## 7. テスト（サーバ）

| 層 | 必須内容 |
| --- | --- |
| domain.game | 規則エンジン設計のベクタすべて |
| application | 版ずれで UPDATE されない、クリアで results が 1 行、アンドゥで手数だけ戻る |
| api | 未認証 401、登録重複 400、ログイン不明 401 |

結合: Testcontainers の SQL Server が使えれば用いる。使えなければローカル SQL Server へのプロファイル。
