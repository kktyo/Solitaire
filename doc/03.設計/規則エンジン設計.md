# 規則エンジン設計

前提: `02.システム要件定義/システム要件定義.md` 5 章、同 API.md の Board / Move。本モジュールは I/O なし。Java / Dart で各 1 実装。

---

## 1. 公開契約

実装言語の型名は合わせなくてよい。入出力の意味は揃える。

```
Deal.initialBoard(rng) -> Board

Rules.isLegal(board, move) -> bool
Rules.apply(board, move) -> ApplyResult
  ApplyResult = { board, cleared: bool } | Illegal

Rules.movableTableauCount(board, column, startIndex) -> int
  // startIndex からトップまで、表向きかつ場札規則の連なりならその枚数。そうでなければ 0

FoundationIndex.suitOf(0..3) -> S,H,D,C
```

`apply` は合法時のみ新しい Board を返す（入力を破壊しない）。不正時は盤面を変えない。

Move は API と同じ:

| type | フィールド |
| --- | --- |
| MOVE | from, to, count |
| DRAW | なし |
| RECYCLE | なし |

Location: `pile` + `index`（STOCK/WASTE は index 無視）。

---

## 2. カード

- `id`: ランク文字 + スート 1 文字。`10` のみランクが 2 桁（例 `10H`）。
- `rank`: A=1 … 10=10, J=11, Q=12, K=13。
- `suit`: S,H,D,C。
- `color`: H,D 赤 / S,C 黒。
- 52 通りのみ合法。重複 id 禁止。

---

## 3. Board 不変条件

永続化・API 入出力の前後で検証する。

1. 52 枚、id 重複なし、欠けなし。
2. `tableau.length == 7`。
3. `foundations` は S,H,D,C の 4 キー。各列は空、または底が当該スートの A で、上へ同一スート・ランク +1 のみ。すべて `faceUp == true`。
4. `stock` の全カード `faceUp == false`。先頭が次にめくる。
5. `waste` の全カード `faceUp == true`。末尾がトップ。
6. 場札: 裏は表より下（ある列で、ある裏の上に裏があってよい。**表の下に裏があってよい**。表の上に裏は禁止）。
7. 場札の表向き連続（列内で最初の表からトップまで）は、隣接が色違い・ランク降順であること。裏の並びは制約しない。

配札直後は 3〜7 を満たす。

---

## 4. 配札

1. 52 id を配列にし、Fisher–Yates。乱数は暗号論的（サーバ本番 `SecureRandom`）。クライアントは配札しない。
2. 列 i（0..6）に i+1 枚。各列末尾だけ `faceUp true`。
3. 残り 24 を stock（順はシャッフル後の残り順を維持）。waste / foundations 空。

テストでは rng をスタブして決定論的盤面を作ってよい。

---

## 5. 合法判定

### 5.1 共通

- `status` はエンジン外。クリア済み盤面への適用はユースケースが拒否する。
- 裏カードを MOVE の対象にしてはならない。
- MOVE の `count` は 1 以上。ソースのトップから `count` 枚。

### 5.2 ソースの切り出し

| from.pile | 条件 |
| --- | --- |
| TABLEAU | index 0..6。列長 >= count。切り出すのは末尾 count 枚。すべて faceUp。かつその count 枚が場札規則の連なり |
| WASTE | count==1。waste 非空。末尾 1 枚 |
| FOUNDATION | count==1。当該スート列非空。末尾 1 枚 |
| STOCK | MOVE としては常に不正（めくりは DRAW） |

### 5.3 行先

自分自身への移動（同一 pile・同一 index）は不正。

**TABLEAU**

- 空: 連なり先頭が K。
- 非空: 先頭が宛先トップと色違い、かつ rank がトップ - 1。

**FOUNDATION**

- count==1 のみ。
- index 0..3 = S,H,D,C。
- 空: カードが A かつそのスートが index のスート。
- 非空: 同一スートかつ rank == トップ + 1。

**STOCK / WASTE** への MOVE は不正。

### 5.4 DRAW

stock が 1 枚以上。先頭を取り `faceUp true` にして waste 末尾へ。

### 5.5 RECYCLE

stock 空かつ waste 1 枚以上。waste を **逆順** にし、すべて `faceUp false` にして stock とする。waste を空。  
（逆順: 捨て札トップが山札の末尾＝最後にめくる側になる。要件「現在の順の逆順」）

例: waste 底→トップ `[A, B, C]`（C がトップ）→ stock 先頭→末尾 `[C, B, A]` すべて裏。次の DRAW は C。

### 5.6 クリア

`foundations` 4 列の `length == 13`。`apply` 後に評価する。

---

## 6. 場札の連なり

列を底→トップ `cards[0..n-1]`、`n-1` がトップ。

位置 `i` からトップまで動かせる条件:

- `cards[i].faceUp`
- すべての `j` in i..n-2 について、`cards[j+1]` が `cards[j]` に対し色違いかつ rank == rank(j)-1
- `j>=i` はすべて faceUp（表の上の裏は不変条件違反）

`count = n - i`。

---

## 7. 擬似コード（apply MOVE）

```
src = takeLast(from, count)      // 失敗なら Illegal
if not canPlace(src.first, to): Illegal
from.removeLast(count)
to.append(src)
if from is TABLEAU and from.notEmpty and from.last.faceUp==false:
  from.last.faceUp = true        // めくり。手数は 1 のまま（別操作にしない）
return board
```

場札の空いた列の新しいトップが裏なら、**その適用の一部として表にする**。アンドゥは `board_before` に裏のまま残っているので自然に戻る。

DRAW / RECYCLE では場札をめくらない。

## 8. テストベクタ

ファイル: [fixtures/rules_vectors.json](./fixtures/rules_vectors.json)。

各要素:

```json
{
  "id": "TV-01",
  "description": "…",
  "board": { },
  "move": { },
  "legal": true,
  "expect": { "board": { }, "cleared": false }
}
```

`legal: false` のとき `expect` は省略。Board は API スキーマ。  
実装は `id` 単位で失敗箇所が分かるようにする。

最低限カバーする ID:

| ID | 内容 |
| --- | --- |
| TV-DEAL | 配札後: 52 枚、列長 1..7、stock 24、表は各列 1 枚（`Deal` を直接呼ぶ） |
| TV-TAB-SEQ | 赤黒降順なら場札へ置ける |
| TV-TAB-KING | K のみ空列へ可。Q は不可 |
| TV-FOUND-A | 空組札へ A |
| TV-FOUND-UP | 同一スート +1 |
| TV-FOUND-MULTI | 2 枚まとめて組札は不可 |
| TV-DRAW | stock 減、waste 末尾が表 |
| TV-RECYCLE | 逆順・すべて裏 |
| TV-RECYCLE-NG | stock 残ありでは不可 |
| TV-FACE-DOWN | 裏は動かせない |
| TV-WASTE-ONE | 捨て札は 1 枚のみ |
| TV-FLIP | 場札移動後、新しいトップが裏なら表になる |
| TV-CLEAR | 最後の 1 枚で `cleared == true`（JSON ではなく、テストコードで組札を組み立てる） |

`fixtures/rules_vectors.json` の盤面は分岐確認用で **52 枚不変を満たさない**。テストハーネスは `skipFullDeckInvariant: true` のとき枚数検査を外す。完全デッキ検査は TV-DEAL とクリア組み立てテストで行う。`expect` は盤面全体ではなく、アサーション用の短いフィールドでよい。

## 9. 不正の一覧（実装チェックリスト）

次はすべて `isLegal == false`。

- count < 1、範囲外 index、未知の pile / type
- 空のソース
- 場札連なりが色またはランクで切れている
- 空列へ K 以外
- 組札へスート不一致、A 以外の空置き、飛びランク
- 山札への MOVE、捨て札への MOVE
- DRAW なのに stock 空
- RECYCLE なのに stock 非空または waste 空
- 同一 loc への MOVE
