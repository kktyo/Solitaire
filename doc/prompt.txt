# やりたいこと
Klondike（定番のソリティア）アプリを新規作成する。
作業場所は親ディレクトリ「ソリティア」配下とする。

- 仕様書は `ソリティア/doc` に作成する
- ソースコードは `ソリティア/code` に作成する
- 仕様を先に固め、合意できる粒度になったら実装する

# 構成
- `ソリティア/code/front` … フロントエンド（Flutter）
- `ソリティア/code/server` … バックエンド（Spring Boot API）

フロントはゲーム画面・操作・アニメーションを担う。
サーバはユーザー・進行中ゲームの保存・履歴・ランキングなど、永続化が必要な機能を REST API で提供する。
ゲームルールの正判定はフロントとサーバの双方で同じ仕様に揃える（チート防止のためサーバ側でも検証する）。

# 技術スタック
- フロントエンド: Flutter（最新安定版）
- バックエンド: Spring Boot（Java、REST API）
- DB: SQL Server
- 通信: JSON over HTTPS（開発時は HTTP 可）

# ゲーム仕様（Klondike）
- 1デッキ52枚。スートは ♠ ♥ ♦ ♣、ランクは A〜K
- 場札（tableau）7列、組札（foundation）4スート、山札（stock）と捨て札（waste）
- 場札は赤黒交互・降順。組札はスートごと A から K まで昇順
- 表向きの連続した正しい並びに限り、まとめて移動できる
- 空列には K（または K から始まる正しい列）のみ置ける
- 山札クリックで1枚めくる（Draw 1）。山札が尽きたら捨て札を裏向きに戻して再利用できる
- 全組札が K まで埋まればクリア

# アプリ機能
必須:
- 新規ゲーム / やり直し
- ドラッグ＆ドロップおよびタップ移動
- アンドゥ（少なくとも直近操作）
- 経過時間・手数の表示
- クリア判定と結果表示
- ゲーム状態のサーバ保存・再開（ログインユーザー）

# 仕様書（doc）に含めるもの
`ソリティア/doc` に、実装者が迷わない粒度で以下を書く。

- 画面一覧と画面遷移
- ルール詳細（合法手・不正手）
- API 一覧（パス、メソッド、リクエスト/レスポンス、エラー）
- DB テーブル定義
- 認証方式
- 非機能（対応OS、レスポンス目安）

ファイルは Markdown で分割してよい（例: `overview.md`, `rules.md`, `api.md`, `db.md`）。

# 実装時の注意
- 仕様書とコードを食い違わせない。仕様を変えたら doc も更新する
- 秘密情報（DBパスワード等）をリポジトリに置かない
- フロントはモバイル（iOS / Android）を主対象とし、画面はカードが操作しやすいレイアウトにする
- サーバはレイヤを分け、ゲームルール判定をテスト可能な形にする
- まずはローカルで front / server / SQL Server を起動して対局〜保存〜再開まで通す
