# 画面一覧・画面遷移

前提: `システム要件定義.md`。対象は Flutter（iOS / Android、縦向き）。同一コードの Web を本番 Container Apps の `/` からも配信する。

---

## 1. 画面一覧

| ID | 画面 | 必須 | 概要 |
| --- | --- | --- | --- |
| SC-BOOT | 起動 | 必須 | トークン確認、current 取得中。操作なし |
| SC-LOGIN | ログイン | 必須 | メール・パスワード |
| SC-REGISTER | 登録 | 必須 | メール・パスワード・確認 |
| SC-HOME | ホーム | 必須 | 再開／新規、直近クリアの要約 |
| SC-GAME | 対局 | 必須 | 盤面、手数、時間、アンドゥ、メニュー |
| SC-CLEAR | クリア結果 | 必須 | 手数・経過時間。対局の上にモーダル可 |
| SC-CONFIRM | 確認 | 必須 | やり直し・新規（進行中破棄）の確認 |
| SC-ERROR | 通信エラー | 必須 | 再試行／ホーム。フル画面またはバナー |

本フェーズに設定画面・ランキング画面・ゲストプレイ画面は置かない。

---

## 2. 遷移

```
SC-BOOT
  ├─ トークンなし／無効 ───────────────► SC-LOGIN
  ├─ 認証済 かつ 進行中あり ───────────► SC-GAME（正本を表示）
  └─ 認証済 かつ 進行中なし ───────────► SC-HOME

SC-LOGIN
  ├─ 成功（進行中あり）───────────────► SC-GAME
  ├─ 成功（進行中なし）───────────────► SC-HOME
  └─ 「登録」────────────────────────► SC-REGISTER

SC-REGISTER
  ├─ 成功 ───────────────────────────► SC-HOME（進行中は通常なし）
  └─ 「ログインへ」───────────────────► SC-LOGIN

SC-HOME
  ├─ 「続きから」─────────────────────► SC-GAME
  ├─ 「新しいゲーム」
  │     └─ 進行中あり → SC-CONFIRM → 実行 → SC-GAME
  │     └─ 進行中なし → SC-GAME
  └─ ログアウト → SC-LOGIN

SC-GAME
  ├─ クリア ─────────────────────────► SC-CLEAR
  ├─ やり直し → SC-CONFIRM → 新対局の SC-GAME
  ├─ ホーム（進行中はサーバ正本のまま）→ SC-HOME
  ├─ 401 処理失敗 ───────────────────► SC-LOGIN
  └─ 通信失敗 ───────────────────────► SC-ERROR（復帰は SC-GAME または SC-HOME）

SC-CLEAR
  ├─ 「ホーム」───────────────────────► SC-HOME
  └─ 「もう一度」─────────────────────► 新規対局 SC-GAME
```

未ログインで対局相当の操作をしようとした場合は、業務 BF-12 どおり SC-LOGIN または SC-REGISTER へ送る。本フェーズは対局 API が認証必須のため、SC-GAME には認証後だけ入る。

## 3. 画面要件

### 3.1 SC-BOOT

- スプラッシュまたは短い待ち。失敗時は SC-ERROR（再試行で BOOT やり直し）。

### 3.2 SC-LOGIN / SC-REGISTER

| 項目 | 要件 |
| --- | --- |
| 入力 | メール、パスワード（登録は確認用をもう 1 つ） |
| バリデーション | 空、メール形式、パスワード 8 文字未満は送信前に表示 |
| サーバエラー | 400 のメッセージを表示（例: メール重複、認証失敗） |
| セキュリティ | パスワードは伏せ字 |

### 3.3 SC-HOME

表示:

- 「続きから」（進行中があるときだけ活性）
- 「新しいゲーム」
- 直近クリアがあるとき: 完了日時、手数、経過時間（SF-12）
- ログアウト

進行中を破棄する新規開始は SC-CONFIRM（「進行中のゲームは破棄されます」）。

### 3.4 SC-GAME

必須表示:

- 組札 4、山札、捨て札、場札 7 列（裏札は裏デザイン、表はスートとランクが読めること。見た目の詳細はフロント設計 5.4）
- 手数、経過時間（秒）
- アンドゥ（履歴が空なら非活性）
- やり直し、ホームへ

操作:

- **ドラッグ＆ドロップ**: 移動可能なカードまたは連なりを掴み、行先の上で離す。
- **タップ**: 1 回目で選択（移動元のトップまたは連なり）、2 回目で行先。行先が不正なら選択を維持または解除し、盤面は動かさない。
- 山札タップ: Draw。空なら Recycle（捨て札があるとき）。両方空なら何もしない。
- 不正ドロップは元位置へ戻す（アニメーション可）。

通信中: 操作は直列。送信中はアンドゥ／やり直しを二重送信しない。

### 3.5 SC-CLEAR

- 「クリア」の文言、手数、経過時間（サーバ確定値）。
- ホーム / もう一度。アンドゥは出さない。

### 3.6 SC-CONFIRM

- 破棄の説明、キャンセル、実行。実行まで正本を変えない。

### 3.7 SC-ERROR

- タイムアウト・5xx・オフライン。
- 再試行（直前 API）、ホームへ戻る。
- 409 はエラー画面にせず、正本で盤面を差し替える。
- 422 はトースト等の短文で足り、SC-ERROR へは遷移しない。

## 4. 表示ルール

- 言語: 日本語。
- 経過時間: `m:ss` または `h:mm:ss`（1 時間以上）。
- カード: 赤スートは赤系、黒スートは黒系。色覚の詳細対応は本フェーズ対象外。描画仕様（四隅インデックス、ピップ、裏面模様、幅上限、重なり）はフロント設計 5.4。
- 選択中カードはハイライトしてよい（業務の「自動組札ハイライト」とは別。移動元の選択表示は必須に含む）。
