# やりたいこと

対局画面の入口と待ち、ドラッグの見た目、山札の Recycle、詰みダイアログの誤表示を直す。

1. **`/game` でセッションが空のとき**「対局がありません」で止めず、画面遷移どおりリダイレクトする。
2. **API 待ち**にローディングを出す（対局の手送信、ホームの新規／続き、起動以外の待ち）。
3. **捨て札（表）をドラッグすると山札（裏）が動く**のを止める。
4. **不正ドロップで元位置へ戻る軌道**がずれているのを直す。
5. **合法ドロップの吸い寄せ軌道**がずれる（正しく重なったように見えない）のを直す。
6. **山札を使い切って Recycle したあと、次の周のめくり順が前周と逆**に見える件を、仕様かバグか決めて揃える。
7. **組札や捨て札からまだ動かせるのに詰みダイアログが出る**なら、誤判定／誤表示を直す。定義を変える場合は正本を先に改訂する。

修正実行の前に、このファイルの「確認事項」に合意する。未決のままコードを変えない。仕様と矛盾する変更は、先に `doc` を改訂してから実装する。

# 背景（現状の実装）

## `/game` 空セッション

`GamePage` は `gameSessionProvider == null` のとき本文「対局がありません」だけ出す。`GoRouter` にリダイレクトガードはない。Web は `Uri.base.path` を初期ロケーションにするため、リロードや直リンクで `/game` に入り得る。Boot は進行中なしなら `/home`、ログイン成功で進行中なしなら `/home`。画面一覧 2 章に「進行中なしの SC-GAME 滞在」はない。

## API 待ち

Boot だけ `CircularProgressIndicator`。ホームの `current` 取得・新規・続き、対局の `POST moves` / undo / create には全画面またはインジケータがない。送信中はボタン非活性と楽観盤面のみ。自動組札中も同様。

## 捨て札ドラッグで山札が動く

上段 `Row`: 組札 4、`Spacer`、山札（`GestureDetector` + 裏）、捨て札（`Draggable`）。捨て札は `childWhenDragging: SizedBox.shrink()`。ドラッグ中に捨て札の幅が 0 になり、`Row` が再レイアウトして山札が横へ跳ぶ。場札列は `Expanded` なので同じ縮み方はしない。

## 戻り／吸い寄せアニメ

`game_page.dart` の Overlay `_fly`（250ms）。始点は `details.offset - _grabLocal`。戻り先はドラッグ開始時のカード `localToGlobal`。成功時の終点は `_tabKeys` / `_foundKeys` の **スロット矩形の左上**。

- `_tabKeys` は列全体（空列や深い列の上端）。着地すべき「新しいトップの位置」（既存枚数 × peek）ではない。
- 組札キーは枠の `Padding`。場札よりは近いが、カード本体と数 px ずれることがある。
- `Listener` の `localPosition` と `Builder` の RenderBox が一致しないと、戻り始点が掴み位置からずれる。

## Recycle の順

規則は捨て札を **現在の順の逆順** にしてすべて裏で山札へ（システム要件 5.3、規則エンジン 5.5）。例: 捨て札底→トップ `[A,B,C]`（C がトップ）→ 山札先頭 `[C,B,A]`。次の DRAW は C。Draw 1 の一般的な Recycle と同じで、**前周のめくり順の逆**になる。実装（Java / Dart）はこの定義どおり。

## 詰み

操作詰み（BR-10）: 合法 MOVE が 1 つもない（場札・捨て札・**組札からの移動を含む**）。かつ DRAW/RECYCLE を山札＋捨て札が元に戻るまで繰り返しても捨て札トップを場・組に置けない。サーバが `GameResponse.stalemate` を付ける。クライアントは `stalemate == true` でダイアログ。エンジン上は組札・捨て札が動かせれば `legalRelocates` は空にならない。

利用者が「まだ組札／捨て札を動かせるのに詰み」と感じるなら、次の切り分けが先。

- 規則上は合法だが UI が掴めない（ヒット・自動中ロック）。
- サーバフラグと表示盤面のずれ、ダイアログの `version` 再利用。
- 定義そのものを「場札が動かない時点で詰み」に変えたい。

# 正本・制約

- 遷移: 画面一覧 2 章。SC-GAME は進行中対局があるときだけ。なしは SC-HOME（未ログインは SC-LOGIN）
- 待ち: SC-BOOT は待ち表示あり。SC-GAME / SC-HOME の通信中インジケータは未規定 → 本スプリントで画面一覧・フロント設計に書く
- ジェスチャ・アニメ: フロント設計 5.3、画面一覧 3.4（戻りは掴み開始の左上、成功は行先スロット左上。場札の着地を列上端にするかトップ位置にするかは未規定）
- Recycle: BR-05、システム要件 5.3、規則エンジン 5.5（逆順）。順を変えるなら正本改訂が先
- 詰み: BR-10、システム要件 5.5a、規則 5.7、API `stalemate`。定義変更は正本が先
- 合法判定の正本はサーバ。配札ソルバ・クリア認定・ドラッグのみ MOVE・自動組札の条件は変えない
- 市販デッキ画像は使わない

# 確認事項（実装前に埋める）

## 1. `/game` に対局がないとき

[推奨] `session == null` なら「対局がありません」を出さず、認証済みなら `/home`、未ログインなら `/login`（または `/boot` に戻して既存の振り分けに任せる）。直リンク・リロードも同じ。進行中があるときだけ SC-GAME を描画する。

[ ] 文言のまま残し、ボタンでホームへ戻すだけ。

合意: （ ◯ ）推奨を採用。空 `/game` は `/boot` へ振り分け

## 2. ローディング

[推奨] 次をブロックする待ちでは、操作不能のうえインジケータを出す。

- ホーム: 初期 `GET current` / 結果、続きからの resume、新規 create（確認ダイアログ中は除く）
- 対局: 手の送信、アンドゥ、やり直しの create、自動組札の連続送信中
- 通信エラー画面の再試行中

Boot 既存のインジケータは維持。楽観カード移動そのものの待ちは、吸い寄せ Overlay のあとに出す（吸い寄せとスピナーを重ねない）。山札タップの応答待ちもインジケータ対象。SN-06（自動リトライしない）は変えない。

[ ] 対局中は出さず、ホームと Boot だけ。

合意: （ ◯ ）推奨を採用。正本は画面一覧 3.3 / 3.4 / 3.7、フロント設計 5.2

## 3. 捨て札ドラッグで山札が動く

[推奨] ドラッグ中も捨て札スロットの幅・高さを維持する（透明プレースホルダ）。`Row` を動かさない。山札はタップ専用のまま、ドラッグに巻き込まない。

場札列の裏札が一緒に動いて見える場合は、同じ「元位置を shrink しすぎ」が原因なら同様に幅を保つ。

合意: （ ◯ ）推奨を採用。正本は画面一覧 3.4、フロント設計 5.3

## 4. 戻りアニメの軌道

[推奨] 03 の合意を守る。離した瞬間の **カード左上** → 掴み開始時の **同じカードの左上**。元カードは Overlay 終了まで出さない。始点の計算がポインタ生座標やページ全体の RenderBox になっていないことを直す。山札タップには付けない。

合意: （ ◯ ）推奨を採用。正本はフロント設計 5.3

## 5. 成功時の吸い寄せ

[推奨] 終点は「行先に置いたあと、そのカード（連なりの先頭）が見える位置」。

- 場札: 既存枚数に応じた peek オフセット上（空列なら列のカード位置）
- 組札: その枠のカード位置

列ウィジェットの上端へ飛ばしてから盤面が切り替わり、カードが下へ跳ねて見える状態は不可。吸い寄せ後に楽観更新＋API。

[ ] 03 どおりスロット矩形の左上のまま（列上端でよい）。

合意: （ ◯ ）推奨を採用。着地は置いたあとのカード位置。正本はフロント設計 5.3、画面一覧 3.4

## 6. Recycle 後の順番

[推奨] **正本どおり逆順のまま**。前周と逆にめくれるのは Draw 1 の Recycle 仕様であり、バグではない。実装が正本と食い違っていれば正本に合わせる（現状は一致）。

[ ] 次の周も前周と同じ順でめくる。捨て札を逆にせず山札へ戻す、または Recycle 定義を改訂する（BR-05、システム要件 5.3、規則 5.5、ベクタ TV-RECYCLE）。

合意: （ ◯ ）推奨を採用。逆順は仕様。BR-05 / 規則 5.5 は改訂しない

## 7. 詰みと組札・捨て札

[推奨] **定義は変えない。** 組札トップを場へ戻せる、または捨て札トップを場／組へ置けるなら詰みではない。その状態でダイアログが出るならバグ（判定・応答・表示のずれ、または UI が合法手を掴めない）として直す。テストに「捨て札または組札から合法 MOVE がある盤では `stalemate == false`」を足す。

[ ] 場札が動かせないとき、組札・捨て札が動かせても詰みとする（BR-10 / 5.5a / 規則 5.7 を改訂）。

合意: （ ◯ ）推奨を採用。定義は BR-10 のまま。誤表示とテストを直す

## 8. 対象外

- ヒント、合法手ハイライト、Draw 3、他バリアント
- カード部品の再デザイン（01〜03 の見た目は維持）
- 配札ソルバ、クリア認定、自動組札の開始条件（場札裏ゼロ）
- Recycle 以外の山札ルール変更（6 で改訂しない限り）

合意: （ ◯ ）推奨どおり対象外

## 9. ドキュメント

[推奨] 実装と同一変更で正本を改訂する。

- 画面一覧 2 / 3.4: `/game` 空は SC-HOME または SC-LOGIN。通信中インジケータ
- フロント設計 5.2 / 5.3: 待ち UI。成功吸い寄せの着地を場札トップ位置にする（5 の推奨を採る場合）
- Recycle を変えるなら BR-05 と規則 5.5 と TV-RECYCLE
- 詰み定義を変えるなら BR-10 と 5.5a。変えないならテストと誤表示修正のみ

[ ] doc は触らずコードだけ。

合意: （ ◯ ）推奨を採用。画面一覧・フロント設計を本スプリントで改訂済み

# 完了条件

- 進行中セッションなしで `/game` を開いても「対局がありません」で止まらず、ホームまたはログインへ移る。
- ホームの新規／続き、対局の手・アンドゥ・自動送りの待ちでインジケータが見え、二重送信しない。
- 捨て札を掴んでも山札（裏）が横に跳ねない。
- 不正ドロップは掴み位置へ一本の軌道で戻り、二重表示しない。
- 合法ドロップは、置いたあとのカード位置へ吸い寄せてから盤面が更新される。
- Recycle の順が、確認事項 6 の合意（正本どおり逆順、または改訂後の順）と Java / Dart / ベクタで一致する。
- 組札または捨て札から合法 MOVE がある盤では詰みダイアログを出さない（7 で定義を変えない場合）。変える場合は改訂した定義と一致する。
- 改訂した `doc` と実装が一致する。
- iOS シミュレータ縦と Web（または `flutter run -d chrome`）で、空 `/game`、ローディング、捨て札ドラッグ、戻り、吸い寄せ着地、Recycle 順、詰みの有無を目視確認する。
